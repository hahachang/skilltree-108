# 108 課綱技能樹

**線上版：<https://hahachang.github.io/skilltree-108/>**
（可加入手機主畫面，離線可用）

把十二年國教課綱的「學習內容」當成技能點，做成可點亮、可追進度的網頁 app。
目前完成自然科學與數學，其餘四領域已完成抽取可行性的前導評估。

## 資料流

```
Downloads/*.pdf ─→ parse_curriculum.py ─→ data/raw_natural.json ─┐
                   parse_math.py      ─→ data/raw_math.json    ─┤
                                                                │
   人工標註：skills_*.json（前置）、subjects_natural.json（科目）│
             taxonomy_natural.json（表三階層）、cross_links.json │
                                                                ↓
                    build_math_skills.py ─→ data/graph_math.json
                    build_natural_skills.py ─→ data/graph_natural.json
                    build_cross_links.py ─→ data/graph_cross.json
                              （三者共用 skill_builder.py 的驗證）
                                                                ↓
                                          web/ ──build_pwa.py──→ docs/
```

## 兩份輸出

- `web/` — artifact 原始檔。`index.html` 沒有 head（由 artifact 平台包上）。
- `docs/` — 靜態網站／PWA，由 `parsers/build_pwa.py` 從 `web/` 包裝產生，
  含 manifest、圖示與 service worker，可安裝到主畫面並離線使用。
  發布步驟見 [PUBLISH.md](PUBLISH.md)。

## 執行

```bash
uv run --with pdfplumber python parsers/parse_curriculum.py '<自然領綱PDF>' data/raw_natural.json 16 58
uv run --with pdfplumber python parsers/parse_math.py '<數學領綱PDF>' 
uv run --with pdfplumber python parsers/parse_handbook_math.py '<數學課程手冊PDF>'
uv run --with pdfplumber python parsers/parse_handbook_natural.py '<自然課程手冊PDF>'
uv run python parsers/build_taxonomy_natural.py
uv run python parsers/build_math_skills.py
uv run python parsers/build_natural_skills.py
uv run python parsers/build_cross_links.py
cp data/graph_math.json data/graph_natural.json data/graph_cross.json web/
uv run --with pillow python parsers/build_pwa.py  # web/ → docs/
python3 -m http.server 8777 --directory docs   # 本機預覽（PWA 版）
```

## 自然科的重構（2026-09）

與數學同一套模型，但有三處領域差異：

- **分支色系用七大跨科概念**（INa–INg），不是 14 個主題——主題太多、顏色分不開。
  國中以上的主題碼透過 `taxonomy_natural.json` 對回所屬跨科概念。
- **六角形（綜合應用）對應國中的 IN 碼**：那是課綱明列的「跨科目主題」，
  本質就是多科技能的匯流，跟數學的「解題」條目同性質。
- **起始年級基準改用學習階段的年級上緣**（Ⅱ→4、Ⅲ→6、Ⅳ→9、Ⅴ→12）。
- **高中必修的跨科依賴只有 8 條**，但每一條都是真的卡點：地科的大氣水平運動
  必須先有物理的牛頓運動定律、潮汐必須先有萬有引力、生物的「遺傳物質為核酸」
  必須先有化學的核酸性質。分科教學會讓這些邊隱形，重構後才看得見。

建圖邏輯已抽成 `parsers/skill_builder.py`，兩個領域共用同一套驗證
（覆蓋率、指向有效性、環路偵測、前置年級反向警示）。

## 兩份課綱的編碼讀法不同（常被問）

| | 數學 | 自然 |
|---|---|---|
| 第 1 碼 | 主題（N 數與量、S 空間與形狀…） | 科別前綴（**僅高中**：B生物/P物理/C化學/E地科）＋ 主題／次主題碼；國小是 INa–INg 跨科概念 |
| 第 2 碼 | **年級**（1–12），直接看得出來 | **學習階段**：Ⅱ＝3–4年級、Ⅲ＝5–6年級、Ⅳ＝7–9年級、Ⅴc＝高中必修、Ⅴa＝高中加深加廣選修 |
| 第 3 碼 | 流水號 | 流水號 |

`PEb-Ⅴc-4` ＝ 物理・力與運動・高中必修・第 4 條。

### 國小／國中的科目歸屬怎麼來的

課綱只在高中給了科別前綴，但國中的次主題碼**可以從高中反推**——`Da` 在高中
是 `BDa`，所以是生物。實測 38 個次主題可唯一反推，覆蓋國中 226 條中的 159 條。

反推不到的有兩類，定義在 `data/subjects_natural.json`：

- `Ma`/`Mb`/`Mc`/`Na`/`Nc`/`Ba` 在高中本來就跨多科（例如 `Ba` 同時有
  `CBa` 與 `PBa`），只能逐條判定。
- 國小的 `INa`–`INg` 是跨科概念，沒有任何機械依據，127 條全部人工標註。

結果分布：物理 202、化學 198、生物 169、地科 157、跨科 53。

**自然科無法從編碼看出確切年級**——Ⅳ 涵蓋七、八、九三個年級，課綱刻意不綁定。
因此 `build_natural_skills.py` 的 `tier` 取該階段的**年級上緣**（Ⅳ→9），
供「起始年級」基準判定使用；節點另外帶 `subject` 欄位標示科別。

## 聚焦＝重新排版，不是高亮

在 779 個節點、最寬一層 57 個（4446px）的圖上高亮一條鏈，兩端往往同時
在視窗外，等於沒有高亮。實測把單一節點的祖先＋子孫抽出來重排，寬度會
掉到整張圖的 7–22%（多數 300–1000px，一個螢幕看得完）：

| 聚焦節點 | 鏈上節點 | 最寬一層 | 寬度 |
|---|---|---|---|
| `Eb-Ⅳ-11` 加速度運動必受力 | 169 | 13 | 1014px |
| `CJd-Ⅴa-4` 酸鹼游離常數 | 97 | 9 | 702px |
| `BGa-Ⅴa-3` 遺傳訊息的複製 | 65 | 4 | 312px |
| `INa-Ⅲ-1` 粒子觀（樞紐） | 393 | 30 | 2340px |

因此點節點預設進入「只看這條鏈」，可切回「在整張圖上看」。
`layout()` 因此改成純函式（回傳 pos 表而非寫回節點），兩套座標才能並存。

**不要改用「滑鼠移到線上顯示箭頭」**：觸控裝置沒有 hover，而 1.4px 的線
在交錯密集處也點不準；而且問題本來就是另一端在畫面外，看不到那條線。

## 數學的前置關係：官方優先

國教院《數學領域課程手冊》逐條列了「先備／連結／後續」，**課綱本身沒有
這些資訊**。`parse_handbook_math.py` 抽出來之後，`build_math_skills.py`
採「官方優先」合併：

- 手冊有列先備的條目（138 條）→ 用官方的
- 手冊沒列的（89 條）→ 退回 `skills_math.json` 的人工標註

不能全面改用官方，因為 227 條裡只有 138 條有列，全換會讓其餘條目變成
孤兒、整張圖斷開。

編碼層級要對齊：手冊講的是課綱條目，圖裡可能拆成 a/b/c。指向被拆解的
條目時取**最後一個**子技能（子技能本來就串成鏈，要到最後一個等於要整條
都會）；被拆解條目本身的官方先備掛在**第一個**。

採用後的結構變化很大——**最長鏈 27 層 → 19 層**，因為官方只列直接先備，
比人工標註稀疏。例如 `F-10-3 多項式不等式` 從 L26 降到 L16。

人工標註與官方的吻合度：吻合 91、官方有而人工漏 149、人工有而官方沒列
153。`skills_math.json` 保留不動，隨時可以切回純人工版。

## 技能卡片裡的課程手冊：分塊呈現＋跳到 PDF 對應頁

手冊是寫給老師的，「基本說明」「條目範圍」是教學重點與範圍界線，價值比
前置關係更高。原本整條解析是一整片文字塞進 `<pre>`，讀不下去也看不出哪段
是什麼；現在照手冊自己的小標切塊（`split_blocks()`）：

| 小標 | 條數 | 中位數 | 卡片上的處理 |
|---|---|---|---|
| 基本說明 | 180 | 359 字 | 收合 |
| 釋例 | 170 | 507 字 | 收合，標明「圖表沒有重製」 |
| 條目範圍 | 159 | 114 字 | **預設展開** |
| 評量 | 141 | 108 字 | **預設展開** |
| 備註 | 131 | 50 字 | **預設展開** |
| 錯誤類型 | 131 | 98 字 | **預設展開** |
| 說明／探索／注意 | 40 | — | 收合 |

**釋例整合不了**——手冊的釋例多半配圖、表或算式版面，抽出來只有文字。
所以改成每個區塊旁邊掛一顆頁碼，點了在新分頁開國教院的 PDF 並跳到那一頁。

### 頁首害我砍掉一半的內文（2026-09 修正）

換版重抽時才發現的：〈肆、學習內容解析〉這一行是**單數頁的
頁首**，整章出現 259 次，長得和 STOP 要擋的「章名」一模一樣。結果**任何橫跨
偶數頁→單數頁的條目，都在翻頁處被砍斷**——修好之後字數從 135,399 變成
274,916，**整整少抽了一半**。

被砍掉的那一截剛好是條目的後半段，所以整批小標幾乎都消失了：

| 小標 | 修正前 | 修正後 |
|---|---|---|
| 釋例 | 103 | 170 |
| 條目範圍 | 112 | 159 |
| 評量 | **0** | 141 |
| 錯誤類型 | **0** | 131 |
| 探索 | **0** | 18 |

「錯誤類型」（手冊列的學生常見錯誤與處理建議）整批沒抽到卻毫無徵兆，因為
每一條看起來都「有內容」。

同時修掉第二個洞：STOP 的 `\d{1,2}年級…學習內容解析` 比不到
「11 年級數學 A 學習內容解析」——手冊在數字和中文之間排了空格。頁首問題一補、
這道終止條件失效就浮出來，`D-10-4` 又吞掉 9.8 萬字。章名與頁首現在都先
`re.sub(r"\s+", "", ln)` 再比。

### 頁碼有兩種，不能混用

- **PDF 頁次**：`#page=` 要的就是這個，存在 `page`
- **書上印的頁碼**：頁尾那個數字，存在 `folio`，差十幾頁（前面有序與目次）

卡片顯示 `folio`（使用者手上任何一份印本都對得上），連結帶 `page`。

### 連到線上版之前先對過頁次

抽取用的是本機那兩份 PDF，連結卻指向國教院現在掛的版本，版本不同頁次就會
錯。兩本都逐條核對過：

- 數學：用 **114 年 1 月更新版**，而且**抽取的檔案和連結指向的檔案 md5 相同**
  （`48124083…`）——不是「版本相近」而是同一個檔，頁次不需要再另外核對。
  國教院這份手冊改過三版（107/12 → 113/3 → 114/1），782 頁的頁次一路沒變，
  改的都是內文，而且每一版都修掉真的錯誤：

  | 版本 | 落在抽取範圍內的修正 |
  |---|---|
  | 113/3 | `N-6-9` 釋例答案：「小方…25 歲／媽媽 50 歲」→「小芳…20 歲／媽媽 40 歲」 |
  | 114/1 | `N-4-7` 錯誤類型：「20 個 0.1 要記成 0.2」→「20 個 **0.01** 要記成 0.2」；「請處說明」→「請**清楚**說明」 |

  114/1 那條特別值得留意：舊版寫的「20 個 0.1 記成 0.2」本身就是錯的
  （20 個 0.1 是 2），而它出現在教師「怎麼糾正學生小數錯誤」的段落裡。
- 自然：本機與線上都是 108 年 1 月定稿版，544 頁，
  **整份抽出來的 JSON 完全相同**。

### 順手修掉的一個假資料

切塊之後才看出來：**有 30 條（N-1-4、N-5-10、S-9-5…）手冊根本沒有解析**，
原本存進 `text` 的是隔壁「新舊課綱對照表」滲進來的儲存格碎片
（「（九年一貫）3-n-11…」「⟹」「二、四」），卡片上卻當成「教學解析」顯示。
現在小標出現之前的行一律丟掉，這 30 條就不再有解析區塊——但它們的
先備關係要留著，`merge_official()` 靠那個做官方優先。

## 自然的課程手冊：能給的不是前置

《自然科學領域課程手冊》和數學那本體例完全不同。它的〈肆、學習重點解析〉
開宗明義寫著：國小與國中的解析請看領綱附錄，手冊自己只解析高中與探究實作。
**所以自然科沒有逐條的「先備／連結／後續」可用，「官方優先」在自然科做不到，
自然科的 1282 條前置仍然全部是人工判斷。**

手冊真正逐條給的東西散在五張版面各異的表裡，`parse_handbook_natural.py`
把它們抽成 `data/handbook_natural.json`（313 條、380 段）：

| 區段 | 頁 | 逐條給的是 |
|---|---|---|
| 國小新舊對照 | 17–24 | 為什麼放在這個學習階段、從哪一階段調來 |
| 高中 99 課綱對照 | 45–64 | 與 99 課綱的差異、對應的舊教材綱要 |
| 加深加廣課程 | 107–112 | 這一條屬於哪一門選修課（只有生物科有表，57 條） |
| 化學建議章節 | 135–142 | 官方建議的單元／章節順序與教材教法 |
| 地科教學建議 | 143–152 | 建議教材與教學方式、學習內容說明 |

三處踩到的坑，都是「看起來成功但其實錯了」那一類：

- **欄位不能用索引對**。合併儲存格會讓資料列相對表頭整列位移（p46 表頭在
  index 1/4/7/10，資料列卻在 0/3/6/9）。改成用表頭儲存格的 **x 範圍**比對。
- **「建議章節順序」一個表頭橫跨兩個子欄**（單元／章節），而且兩欄的折行在
  文字裡交錯（「物質的／組成」夾著「1.物質的狀／態」），只能按 x 切，
  按「開頭有沒有編號」切會黏成「物質的組成態」。
- **手冊的編碼有印錯的**。`EFb-Ⅴc-1`（由地球觀察恆星的視運動）被印成
  `EFa-Ⅴc-1`，而 `EFa-Ⅴc-1` 本身是另一條真實存在的條目（地震波分層）——
  撞號沒辦法用別名表處理。改成拿編碼後面接的**條文原文**回頭驗，對不上就
  依原文改回，共修掉 5 處；另有 3 處是課綱定稿前的舊編碼，人工比對原文後
  列在 `ALIAS` 裡。

### 唯一能拿來對帳的官方排序

化學必修的「建議章節順序」是手冊裡唯一的官方序列，46 條必修全在表內。
`build_natural_skills.py` 拿它跨單元核對人工標註的前置方向：**35 條可比對的邊
裡，34 條與官方順序一致**。唯一反向的是
`CEc-Ⅴc-1 氣體基本性質 → CAb-Ⅴc-1 物質的三相圖`——手冊把三相圖排在第一單元。
這條**刻意保留**：章節順序是教學順序，不等於知識依賴，三相圖要讀懂本來就需要
氣體性質。核對只印警告，不改資料。

## 手機的兩張抽出式卡片（左＝技能詳情、右＝參數）

年級、圖例、檢視、模式、著色、縮放這六組控制項在 390px 寬的螢幕上要佔掉六行。
實測 375×812：**地圖只有 382px、佔畫面 47%**。改成從右緣往左拉出一張卡片之後，
**地圖變成 576px、佔 71%**（多了 194px）。

- **只在 ≤560px 生效**。寬螢幕維持原本攤開的工具列——那裡橫向空間夠，
  而且圖例攤開同時就是分支篩選器，收起來反而更難用。
- **手勢要自己吃掉**。右緣的抓取條設 `touch-action:none`，否則地圖的原生
  捲動會先接走手勢。抓取條只佔中段 36% 高度，避開頁首與瀏覽器底部列。
  代價是最右側約 20px 的節點點不到，可以橫向捲動避開。
- **卡片是常駐元素，不在 `main` 裡**。控制項會呼叫 `render()` 重畫 `main`，
  放在裡面每按一次就會被關掉。卡片自己的內容在 `renderMap()` 裡重填，
  `.open` 狀態因此跨重繪保留。
- **技能詳情改從左緣拉出來**。寬螢幕它停靠在地圖右側、排進版面流，不覆蓋
  高亮的依賴鏈；窄螢幕沒有那個空間，原本它接在地圖下方，每點一個節點都要
  往下捲才看得到。兩側共用同一份手勢實作（`edgeDrag()`），只差一個方向參數。
  **點節點不會自動彈出卡片**，只把內容備好——點技能的當下要看的是它在圖上的
  位置與依賴鏈，卡片蓋上來反而擋住。想讀再從左緣往右拉。因為它不再自動出現，
  提示列多一句「技能說明從左緣往右拉」，否則沒人知道有這個東西。
  （iOS Safari 的左緣返回手勢可能搶走這一下；加到主畫面的 PWA 沒有返回手勢。）
- **卡片裡只留一顆按鈕**：「點亮這個技能」。「調整起始年級」是設定，屬於頁首的
  「進度」，不該混在技能卡片裡；「關閉」只留給寬螢幕的停靠式側欄——窄螢幕的
  卡片往左滑、點暗底、Esc 都能收，再放一顆按鈕只是佔位置。起始年級以下的技能
  兩顆都沒有，卡片直接結束在出處那一行。
- **兩張卡片不同時開**，開一張會收掉另一張。
- **離開地圖就要收掉左卡片**。它是覆蓋式的：按「調整起始年級」跳到進度頁、
  或輸入搜尋，卡片會整個蓋住要看的內容。`render()` 裡只要 `state.panel`
  或搜尋字串非空就 `closeDetailPanel()`。
- **不要把 `visibility` 放進 `transition`**。`transition:transform .22s,
  visibility 0s linear .22s` 會讓 transform 的過渡卡在起點、面板永遠滑不進來；
  收起時改用 `pointer-events:none` 就好，元素本來就已經移出畫面。

> 內嵌瀏覽器測試陷阱：那裡的 `document.timeline.currentTime` **不會前進**
> （實測 300ms 之後仍是 0），CSS transition 因此永遠停在起點，量到的位置會
> 是「收起」的位置。要驗證版面位置，先用 `transition:none` 蓋掉再量。

## 技能卡片為什麼會出現「同一個編碼兩次」

R-5-3〈以**符號**表示數學公式〉的卡片上，R-4-3〈以**文字**表示數學公式〉
同時出現在「前置技能」和「關聯條目」——看起來像資料重複，其實是兩種關係
都成立：一個是我判定的學習順序，一個是課綱自己寫出來的編碼。

處理方式：

- **已列在前置或後續的，不再列進關聯條目**。66 條延伸關聯裡有 34 條是這種
  重複，隱藏後剩 32 條是真正「沒有依賴關係、但課綱點名」的。
- **標題從「課綱原文點名」改成「課綱點名」**，並註明來源可能是條文或附錄說明。
  R-5-3 就是附錄說明提到 R-4-3，條文本身沒有。
- **卡片補上「課綱附錄的學習內容說明」**。條文常常只有一句，真正寫「教到什麼
  程度、和哪一條什麼關係」的是附錄。數學 227 條裡 166 條有，總共才 8,352 字，
  直接帶進 `graph_math.json`。R-5-3 的附錄就直接回答了這個疑問：
  「本條目並非取代『文字表示公式』（R-4-3），後者較易理解之優點仍可保持。」

自然科的附錄是獨立的〈附錄四：學習內容說明〉（領綱 p95–235），由
`parse_natural_notes.py` 另外抽，**774 / 779 個技能有**。

## 自然領綱的〈附錄四：學習內容說明〉

數學領綱把說明做成學習內容表裡的一個「備註」欄，所以 `parse_math.py` 順手
就收了；自然領綱是獨立的附錄四（p95–235），一直沒抽。
`parse_natural_notes.py` 補上，**774 / 779 個技能有說明**，共 6 萬字。

版面有四種表頭，但都成對出現「學習內容｜學習內容說明」，所以不照欄位索引取，
而是**先認出每一組「內容欄→說明欄」的 x 範圍再配對**——國小是兩個學習階段
並排的兩欄式，一列裡有兩條不同編碼，照索引取一定會把第三學習階段的說明掛到
第二學習階段的條目上。

### 說明怎麼對回條目：看開頭那個數字

國中與高中是**一個儲存格裡列好幾條**（`Bc-Ⅳ-1`～`Bc-Ⅳ-4`），說明欄則寫成
「1-1…2-1…3-1…」。開頭那個數字是**條目的流水號**，不是說明自己的編號。
只取整格當成第一條的說明，國中高中會少掉八成（實測只抽到 321 / 779）。

開頭有四種寫法，各自的歸屬不同：

| 寫法 | 意思 | 掛給誰 |
|---|---|---|
| `1-1`、`2-3` | 第 1 條的第 1 則說明 | 該條目 |
| `5~7` | 一段說明涵蓋第 5～7 條 | 那一段範圍的每一條 |
| `‧` 開頭 | 整組共通的提醒 | 這一列所有條目 |
| 沒有任何標記 | 兩種情況，要分清楚 | 見下 |

**沒有標記的最容易搞錯**：如果這一列本身有編碼，它是整組共通的說明
（`Na-Ⅳ-2`～`Na-Ⅳ-5` 共用一句「建議以資料蒐集、議題討論…」）；如果這一列
沒有編碼，那是被頁尾切斷、翻頁過來的**半句話**，要接回上一則。分不清楚的話，
`PEb-Ⅴc-5` 的說明會只剩一個「程。」。

### 另外三個坑

- **表頭儲存格會把第一列資料一起吃進來**（p207 的表頭是
  「學習內容⏎水可自解離產生H＋與OH－。」），所以比對表頭要用 `startswith`
  不能用相等。順序還不能反——「學習內容說明」本身就以「學習內容」開頭。
- **前綴要取整格裡最多數的**，不能取第一個。附錄的 `BLb-Ⅴa-1` 在圖裡被合併成
  別名 `BFc-Ⅴa-1`，拿它當前綴會把同一格的 `BLb-Ⅴa-3`、`-4` 組成不存在的
  `BFc-Ⅴa-3`、`-4`。
- **別名要一起查**：`BLb-Ⅴa-1`→`BFc-Ⅴa-1`、`BMc-Ⅴa-1`→`BGa-Ⅴa-7` 是領綱
  自己把同一個概念列了兩次，`skills_natural.json` 已經合併，掛說明時要跟著查。

剩下 5 條真的沒有：`BGa-Ⅴa-3`、`BMa-Ⅴa-2`、`BMb-Ⅴa-8`、`PEb-Ⅴa-12`、
`PEb-Ⅴa-13`（附錄的編號直接從 11-1 跳到 14-1）。

## 關鍵節點怎麼算

`skill_builder.py` 對每個技能算兩個指標：

- **reach**：它總共解鎖多少下游技能（影響範圍）。前端用它決定節點半徑
  （開平方壓縮，否則根節點會大到蓋住鄰居），所以關鍵樞紐自己會浮出來。
- **gate**：把它拿掉之後，有多少技能再也走不到。這是真正的必經關口。

前端另外即時算「現在最該學的」——在目前進度下可學的技能中，依
「學完會立刻解鎖幾個」排序。**不要用連鎖可達性計算**：解鎖規則是
「前置全部完成」，遞迴傳播的話每個節點都會得到相同答案（實測全為 0）。
改用兩個可驗證的數字：立刻解鎖數，以及下游未完成技能總數。

## 抽取踩坑（動 parsers/ 之前務必看）

1. **不要用 `pdfplumber.extract_table()`**。它依偵測到的 cell 高度裁切文字，自然領綱
   一個 cell 塞十幾條條目時，尾端條目會整條消失（實測 `INb-Ⅱ-5` 不見）。
   `pdf_columns.py` 一律只借用表格 bbox 當範圍，文字自己從 word 座標重組。
2. **一頁可能有兩個幾何不同的表格**（學習表現表尾接學習內容表頭）。只取
   `find_tables()[0]` 會讓第二個表的編碼欄與敘述欄被錯誤切割，必須逐表處理。
3. **編碼有時排在行尾**（`水可自解離產生H＋與OH－。CJd-Vc-1`）。編碼框與敘述框
   各自獨立，y 座標略有落差，依 y 分行時編碼會掉到行尾，導致該條敘述被掛到上一個
   編碼、而自己變成空字串。`fix_trailing_codes()` 專門處理這件事。
4. **階段碼混用全形羅馬數字與 ASCII**（`Ⅴc` 與 `Vc` 並存），同一節點會變成兩個 key，
   必須先正規化再入庫。
5. **跨頁續行的歸屬不能用欄位索引**，換頁時表格幾何會變、索引錯位。
   改用編碼自帶的學習階段當歸屬鍵（課綱每一欄本來就是一個學習階段）。
6. **strip_noise 必須在 clean() 之前執行**。「課題N：…」規則以 `[^\n]*`
   比對到行尾，若換行已被壓掉，整段續行會被當成課題標題刪光。
7. **整欄只有續行、沒有任何編碼的欄位不能跳過**（跨頁尾巴），
   否則那段文字會憑空消失。依表頭判斷所屬階段後接回上一條。
8. **編碼可能整欄下移一行**（編碼框垂直置中）。修正前要先做整欄型態偵測，
   逐行套用會在國中頁面的主題交界誤觸發，把下一條的開頭吃進上一條。
9. **數學公式會被 PDF 排版打散**（`A-8-1` 的乘法公式抽出來是亂的），這是 PDF 內嵌
   數學排版的本質限制，少數條目需人工補。

## 跨領域連結（自然↔數學）

課綱兩份文件互不引用，79 條邊全部是人工判定，定義在 `data/cross_links.json`，
方向一律是**數學→自然**。判準是「不會這個數學就真的算不出／看不懂那個自然
條目」，不連「用得到但不是門檻」的關係，**每一條都必須寫理由**（build 會擋）。

分布：物理 37、化學 23、地科 10、生物 6、跨科 3。
最常被需要的數學是「比與比例式」（13 條）與「比與比值」（7 條）——
高中自然的數學門檻，大宗其實是國中的比例概念，不是高階內容。

跨領域前置**同樣會擋住解鎖**，並在圖上畫成虛線輪廓，跟「卡在自然科自己的鏈」
區分開來。依賴鏈的聚焦仍只在單一領域內展開，跨領域關係以詳情面板的
「需要的數學」／「自然科哪裡會用到」雙向呈現。

`build_cross_links.py` 驗證編碼存在、不重複、附理由，並檢查數學前置是否
排在自然條目之後（那代表標錯，或課綱本身有順序衝突）。

## 驗收方式

抽取完一定要跑流水號連續性檢查：同一 `(topic_code, stage)` 的 `seq` 必須是
`1..n` 沒有缺口。有缺口就代表有條目被版面吃掉了。

## 數學的「重構」模型（2026-09 第二版）

第一版直接沿用課綱骨架：同主題按流水號串 `seq`、跨學習階段串 `stage`。
問題是那 1028 條邊全是**編號順序**，不是知識依賴——它等於宣稱「N-6-6 學完才能學
N-6-7」，但那只是印刷順序。

第二版把這兩種行政鏈整個拿掉，改成：

- **節點允許拆解**：`N-6-7 解題：速度` 混了比值、單位換算、平均速度三件事，
  拆成 `N-6-7a/b/c`。每個技能保留 `src` 指回課綱原條目，可追溯。
- **別名合併**：課綱自己標「同 S-1-1」的重複條目合併成一個技能。
- **前置＝人工標註的真實概念依賴**，定義在 `data/skills_math.json`。
  課綱原文點名的編碼（如「連結加與減的關係（R-2-4）」）另存為「延伸關聯」，
  不當前置。
- **縱軸改用 depth**（依賴圖上的最長路徑），不是年級。

結果：240 技能 / 387 前置邊 / 27 層，5 個真正的起點
（`N-1-1a`、`N-1-5`、`N-1-6`、`S-1-2`、`D-1-1`）。

`build_math_skills.py` 會強制驗證：覆蓋率（每個技能都要有 prereq 標註）、
指向有效性（前置不可指向已被拆解的母條目）、**環路偵測**。任何一項失敗直接中止。

觀察到的結構事實：幾何（S）鏈比代數（N→A）淺得多。`S-8-4 全等圖形`（八年級）
深度只有 5，而同為八年級的 `A-8-7b 配方法` 深度 22。最長鏈 27 層從小一加法
一路到高一多項式不等式，中間沒有捷徑。
